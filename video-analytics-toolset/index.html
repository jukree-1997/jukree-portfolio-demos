WHAT CONNECTS THE WORKFLOW

The handoffs matter.

LOCAL PORTFOLIO DRAFT
01 / SHARED CAMERA CONTEXT

One camera, consistent identity.

Project, branch and camera identity keep recordings, configuration, processing and reports aligned. Model settings, reference frames, zones and lines describe how to interpret that camera's view.

02 / STORAGE WITH A PURPOSE

Raw events and reports have different jobs.

Video_Process handles MongoDB connections and destinations for raw events, configuration snapshots and report data. Reports derive from stored events, so reviewing a period does not always require running detection again.

03 / OPERATIONS WHEN NEEDED

Capture and monitoring support the work.

Video_Recorder can capture RTSP footage, upload completed files and recover interrupted work. Monitor_Service supports heartbeat/status monitoring and operational notifications. These are separate supporting tools.

CONCEPTUAL ARCHITECTURE

Separate the operator's tasks.
Keep the project context connected.

Model_Config supplies camera and inference configuration. Video_Process coordinates processing and report generation. Shared identity, configuration and recording conventions connect the steps without requiring staff to edit scripts for each task.

The older pipeline already provided analytics and zone/line drawing. My work added the new toolset and redesigned how staff configured and operated those capabilities.

MY CONTRIBUTION / MAR–MAY 2026
Make the pipeline usable
by the team running it.
At Baksters Co., Ltd., I independently built these tools and redesigned parts of the operating workflow around an existing customer traffic-analysis pipeline.
THE PROBLEM
Routine tasks needed developer involvement.
The previous workflow was developer-operated. It already had a zone/line drawing interface, but I found that interface difficult to use and the broader processing setup needed a clearer operator workflow.
WHAT I BUILT
Interfaces, configuration and handoffs.
I designed and implemented the desktop tools, improved zone/line configuration, and organized model setup, recording, processing, storage and report preparation into more accessible tasks.
THE VALUE
Other staff could run customer work.
The toolset enabled colleagues beyond the development team to operate the pipeline and was used for completed customer processing. No quantified time saving or production dashboard ownership is claimed.
Scope of this HTML explanation
All illustrations, paths, configuration examples and metrics on this page are fictional. No customer footage, company application source, model weights or credentials are included. This is a self-contained HTML file with inline CSS, JavaScript and SVG: it works offline, makes no external requests and stores nothing across reloads.
The real toolset's detection, tracking, database writes, video capture, cloud uploads and report generation are explained rather than executed. The drawn journey is a browser animation, not a reconstruction of the original analytics algorithms. This is an approved portfolio showcase.
